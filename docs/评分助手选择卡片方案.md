# 评分助手选择卡片方案（让用户点选，不让用户打字作答）

> 状态：维护者 2026-11-16 确认，Q1–Q6 按推荐，Q7、Q8 见第 10 节。已在分支 `claude/assistant-choice-card`（基于 #111）实现；2026-11-16 候选镜像评测达标（54/54，0.0590 美元），报告 `docs/评测报告/评分助手/2026-11-16-133656-choice-card-gemini-2.5-flash.md`。
>
> 前置：本地未提交的修复（等选文件时点名标准即换标准、`rubric_name` 认序号、`rubric_list` 结果里提示不要写“用 r1”）先作为单独的 PR 合入，本方案在它之上做，并把它保留为打字时的兜底（Q6）。

## 1. 背景

2026-11-16 生产对话：

1. 用户在等选文件时说“选取其他评分标准”；
2. 助手（Agent）写了一段文字列表“1. 开题报告-2026-2027 v1.0 (通用文档) 2. 毕业论文评分标准-V1 v1.0 (毕业论文)”，请用户说“用开题报告”或“用 r1”；
3. 用户回“2”，助手回“没有找到您说的评分标准”。

直接原因已在前置修复里处理。但根子在交互：**选项是固定的几个对象，却让用户打字回答，再由模型或代码去猜用户指的是哪一个**。打字作答有三处天然的不确定：

- 用户可能回序号、名称、简称或文档类型，每一种都要解析；
- 序号对应的是模型自己写的列表顺序，代码按工具结果的顺序取，两者不保证一致；
- 引用编号（`r1`）只在一个回合内有效，用户也看不到它，下一句话用不上。

## 2. 现状

### 2.1 选择卡片是逐场景写的

| | 选任务 `choose_batch` | 选材料 `choose_paper` |
|---|---|---|
| 生成 | `queries.py` 的查询图里单独拼 | 同一文件另拼一张，字段不同 |
| 点击 | `runner._handle_select` 单独一个分支，带 `next_intent` 接着查询 | 另一个分支，直接打开材料结果 |
| 前端 | `AssistantCard.vue` 按类型分别渲染按钮 | 同左 |
| 压缩摘要 | `compaction.py` 按类型写“选了…” | 同左 |

这两张卡片只出现在规则模式（查询图）里。

### 2.2 Agent 回复没有“请用户选”的表达

`reply` 只有 `text`、`cards`、`next_steps`、`help_refs`：

- `cards` 里的编号渲染成**数据卡片**（任务概览、材料结果），用来看，不是用来选；
- 没有卡片的对象（评分标准、评分项）由 `turn.attachments` 按工具结果列成几行文字；
- `next_steps` 是固定的快捷动作（开始评分、导入……），不带对象。

所以 Agent 要用户在几个对象里挑一个时，只能写文字列表，等用户打字。系统提示里那句“真的有多个候选才把候选告诉老师，请他选”，落到界面上就是一段文字。

## 3. 目标与不做的事

目标：

- 凡是“在几个对象里挑一个”，用户**点按钮**完成；按钮上的名称、版本来自工具结果，不经模型转述。
- 由模型判断“这次是让用户选，不只是列给用户看”，在 `reply` 里显式标明；选项与点击后的动作由代码负责。
- 一套卡片、一套渲染、一个点击入口。以后加一种可选对象，只在后端登记“点了之后做什么”。

不做的事：

- 不替代确认卡片（开始评分、重试、取消、放弃上一步）：那是“是 / 否”，已有各自的卡片与写动作守卫。
- 不替代 `next_steps`：那是固定动作，不带对象。
- 不让模型决定点击后的写动作：点击后做什么由代码按用途登记，模型只选用途。
- 不支持多选。

## 4. 回复格式：新增 `choose`

**通用性原则**：选择卡片不绑定任何角色或业务场景。字段、卡片、提示词里关于选择的说明一律写“用户”，不写“老师”；用途清单只描述“选什么对象、选来做什么”，不描述谁在选。教师、管理员或以后的其他角色用的是同一套。现有系统提示、工具说明与给模型看的工具结果里的“老师”在 `@7` 一并改成“用户”（Q8，维护者 2026-11-16 定），见第 6.8 节。


`reply` 加一个可选字段：

```json
{
  "text": "可以换成下面任意一份：",
  "choose": {"purpose": "use_rubric", "refs": ["r1", "r2"]}
}
```

- `purpose`：枚举，见第 5 节。模型只能从清单里选。
- `refs`：2 到 10 个本回合工具结果里出现过的编号，**种类必须与用途一致**（`use_rubric` 只收 `r`）。

校验（`reply.validate_reply`，不合格整体作废、重试一次，与现有规则一致）：

| 情况 | 处理 |
|---|---|
| `purpose` 不在清单、`refs` 种类不符、编号不在本回合工具结果里 | 作废，提示改正 |
| 只有一个候选 | 作废，提示“只有一个就直接用，不要让用户选”（与系统提示“只有一个直接用”一致） |
| `choose` 与 `cards` 里出现同一个编号 | 作废：同一个对象不能既展示又让选 |
| `text` 以冒号结尾 | 有 `choose` 时放行（后面就是按钮） |
| `text` 里自己又写了一遍编号列表（行首 `1.`、`·` 后跟某个候选的名称） | 去掉这些行，不作废 |
| 用途在当前状态下不可用（如 `use_rubric` 但已经上传、任务锁定了标准） | 作废，提示“现在不能换评分标准，原因……” |

有 `choose` 时，`turn.attachments` 不再把这些编号列成文字行；工具登记的说明（“选文件之前可以换一份……”）仍附在后面。

## 5. 用途清单（第一期）

| `purpose` | 对象 | 点了之后（代码执行） |
|---|---|---|
| `use_rubric` | 评分标准 `r` | 正在等选文件：恢复同一张选文件卡片的 `change_rubric`（与工作区换标准同一条路）。没有在评分：用这份标准开始评分（走 `_start_flow`，打断保护照常）。已上传、标准锁定：卡片失效，说明原因。 |
| `focus_task` | 任务 `t` | 设为当前任务（与 `choose_batch` 相同），然后**接着回答用户刚才的问题**（第 6.3 节）。 |
| `focus_paper` | 材料 `p` | 设为当前材料并打开结果（与 `choose_paper` 相同），然后接着回答。 |

用途登记在一张表里：`purpose → (对象种类, 显示用的标签函数, 点击处理函数, 当前是否可用)`。加新用途只改这张表与提示词里的清单。

## 6. 实现

### 6.1 卡片

统一类型 `choice`：

```json
{"type": "choice", "status": "proposed", "purpose": "use_rubric",
 "options": [{"id": "<对象 ID>", "label": "《开题报告-2026-2027》v1.0（通用文档）", "current": true},
             {"id": "<对象 ID>", "label": "《毕业论文评分标准-V1》v1.0（毕业论文）"}],
 "context": {"question": "用户原话的前 200 字"}}
```

- `options` 由代码从 `TurnRefs` 取：对象 ID 与标签都来自工具结果，模型给的只是编号。
- `current` 标出当前在用的那份（评分标准）或当前任务，按钮上写“正在用”，可以不点。
- 卡片落库在助手消息的 `cards` 里，与其它卡片一样；点过之后 `status = done`，`result` 记选中的 ID。

### 6.2 点击

`runs` 的 `select`（与 `choose_batch` 同一个入口）：

1. 卡片必须是 `proposed`，选中的 ID 必须在 `options` 里，否则 422 / `ASSISTANT_CARD_STALE`；
2. 按 `purpose` 查登记表，**重新校验**对象可见性（守卫）与“当前是否可用”——卡片可能是几分钟前出的；
3. 执行处理函数；卡片标 `done`。

### 6.3 选完之后接着回答（`focus_task`、`focus_paper`）

用户说“看一下那个任务的进度”，有三个任务，模型出选择卡片；用户点了一个，期望直接看到进度，而不是再问一次。

做法：点击后设好焦点，写一条事件消息“你选了《任务名》”，再用**用户原来那句话**（卡片里存的 `context.question`）跑一次 Agent 回合；这时 `t0` 就是选中的任务，模型直接回答。代价是多一次模型调用（Q3）。

`use_rubric` 不需要：换标准或开始评分本身就是答案。

### 6.4 规则模式与旧卡片

- 查询图里的 `choose_batch` / `choose_paper` 改为生成 `choice` 卡片（`focus_task` 带 `next_intent`、`focus_paper`），点击后的行为不变（Q4）。
- 前端保留对旧类型的渲染，历史消息照常显示；后端保留旧类型的点击分支一个版本，之后删。
- 规则模式目前认不出“换评分标准”这类话，本方案不补（Agent 在生产已开）。

### 6.5 打字作答的兜底

卡片出来后用户仍可能打字回“2”“第二个”“毕业论文那份”。处理顺序：

1. 会话里**最新一张仍是 `proposed` 的 `choice` 卡片**存在，且用户这句话能确定地对上其中一个选项（序号按**卡片上显示的顺序**，或名称唯一包含）→ 由代码当作点了这个按钮，不调用模型；
2. 对不上 → 照常进 Agent 回合；前置修复里的序号与名称匹配仍在（Q6）。

第 1 步解决了“序号对的是模型写的列表还是工具结果顺序”的问题：用户看到的就是卡片，序号按卡片算。

### 6.6 前端

- 新组件 `ChoiceCard`（`AssistantCard.vue` 里按 `choice` 分派）：每个选项一个按钮，`current` 的加“正在用”标记；点击调 `store.select(card.id, {id})`；选完显示“已选：…”。
- 发送中、卡片失效时按钮禁用，与现有选择卡片一致。
- 组件测试补一条；Playwright 不另加：验收后端没有第二份已发布的评分标准，选任务的两条已有用例（按姓名查扣分、查进度）已经走新卡片。

### 6.7 其它要同步的地方

- `agent/context.py`：`reply` 的工具说明加 `choose` 字段与用途清单；系统提示里“真的有多个候选才把候选告诉老师，请他选”改为“有多个候选要用户选时用 reply 的 choose，不要自己列编号，不要让用户说编号”；`CARD_LABELS` 加 `choice`。
- `agent/compaction.py`：`choice` 卡片的摘要写“用户选了《…》”。
- `SYSTEM_VERSION` 升到 `assistant-agent@7`，`PROMPT_FINGERPRINTS` 加一行。
- 契约版本（`core/contract.py` 与前端 `api/contract.js`）升一版：旧页面不认识 `choice`，会显示成空卡片。
- 三文档：ARCHITECTURE（回复契约多一个字段、卡片与点击入口统一）、DECISIONS（本方案的取舍）、RUNBOOK（新排错：按钮点了说“已失效”）。

### 6.8 全局措辞：“老师”改为“用户”（Q8）

范围是**模型看得到的文字**：`agent/` 下的系统提示（`context.py`）、工具说明与参数说明（`business.py`、`catalog.py`）、工具结果里的“提示”“说明”、帮助条目里给模型的部分、压缩摘要（`compaction.py`）、等待说明（`PENDING_DETAILS`）。现有约 98 处。

注意：

- `claims.py` 等**核对模型输出**的规则如果匹配“老师”字样，改成同时认“老师”和“用户”：模型在历史对话里仍可能沿用旧称呼，不能因此误判。
- **给用户看的界面文字**（流程消息、卡片、帮助正文）本来多用“你”，不在本次范围；其中出现“老师”的另行处理。
- 代码注释与内部文档不改。
- 评测集里判定回复用的关键词（如 `reply_not_asks`）若含“老师”，一并放宽。

## 7. 评测（上线前必须）

改提示词后，部署门槛（`assistant_eval_gate`）要求在新指纹上有一轮跑满评测集、门槛全过的正式评测，否则 `ASSISTANT_AGENT_ENABLED=true` 时不部署。

评测集新增条目（`assistant_eval_set.jsonl`），评测器加一个判定键 `choice`（`{"purpose": "...", "required": true}` 或 `"forbidden"`）：

| 编号 | 前置 | 用户说 | 期望 |
|---|---|---|---|
| choose-01 | 开始评分（两份已发布标准） | 选取其他评分标准 | 出 `use_rubric` 选择卡片，等待步骤不变 |
| choose-02 | 开始评分 | 有哪些评分标准 | 调 `rubric_list`，等待步骤不变；出不出卡片都算通过（Q5） |
| choose-03 | 无 | 用课程报告评分标准帮我评一下 | 直接 `action_start_grading`，**不出**选择卡片（用户已经说清楚了） |
| choose-04 | 开始评分 | 换成课程报告评分标准 | 直接 `action_start_grading`（等选文件时就是换标准），**不出**选择卡片 |
| choose-05 | 无（多个任务） | 看一下那个任务的进度 | 出 `focus_task` 选择卡片 |
| choose-06 | 无 | 现在有哪些评分任务 | `task_list`，**不出**选择卡片（只是列给用户看） |
| choose-07 | 无 | 示例学生乙为什么扣分 | `paper_result` 按姓名唯一找到，**不出**选择卡片 |
| choose-08 | 无（没有当前任务） | 第 2 份为什么扣分 | 出 `focus_task` 选择卡片（序号离开任务没有意义） |

评测环境里加了第二份已发布的评分标准（“课程报告评分标准”，通用文档），两份都在。初稿里“只有一份标准”“只有一个任务”“已上传后换标准”三条在共用的评测环境里造不出来，改由后端测试覆盖（`test_choose_is_sent_back_when_it_cannot_be_used`、`test_rubric_buttons_are_refused_once_the_files_are_uploaded`），评测里换成 choose-04、07、08。评测器加判定键 `choice`：`{"purpose": …}` 必须出、`"forbidden"` 不许出。

原有 46 条全部重跑，回归项不能下降。这次同时改了全局措辞（第 6.8 节），所以**只跑一轮完整评测**（54 条，在候选镜像上），作为 `@7` 的上线依据；不达标再调提示词、再跑。

评测要调用真实模型（Vertex 上的 `gemini-2.5-flash`，即 `EVALUATED_MODELS` 里唯一的模型），维护者 2026-11-16 授权跑一轮完整评测；预算沿用 2026-10-22 的授权（每轮不超过 0.5 美元、合计不超过 3 美元），正式运行前先估算并报给维护者。参照 2026-10-29 UI-v2 那一轮：46 条实花 0.0862 美元（估算 0.2565，单轮预算 0.50），累计 0.4291 / 3.00 美元。新增 8 条后单轮约 0.1 美元（估算上限约 0.3 美元）。

## 8. 发布顺序

1. 前置修复单独 PR 到 develop（无提示词变化，可先发）。
2. 本方案代码 PR 到 develop：提示词 `@7` + 卡片 + 评测集新增条目；CI 只跑脚本化假模型的测试。
3. 用工作流 `pgs-assistant-eval` 在候选镜像上跑一轮完整评测（不替换线上），报告提交到 `docs/评测报告/评分助手/`。
4. 门槛通过后随 develop → main 发布。门槛不过时，部署流水线会拦住，Agent 开关不受影响的旧版本继续运行。

## 9. 风险与代价

- **多一种回复字段，模型可能不用或用错**：不用时退回现状（文字列表 + 打字兜底），不会更差；用错由校验作废重试。评测里的 choose-03、06、07 专门看“不该出时别出”。
- **`focus_task` / `focus_paper` 选完多一次模型调用**：费用与延迟各多一个回合（Q3 可选不接着回答）。
- **卡片过期**：对象在出卡片后被删除、标准被下线或任务已上传锁定，点击时重新校验，返回“已失效”并说明原因。
- **旧页面**：契约版本守卫会让旧页面在下一次写操作前刷新。
- **评测要花钱、要时间**：提示词改动无法只靠离线测试上线。
