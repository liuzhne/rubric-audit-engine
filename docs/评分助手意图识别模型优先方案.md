# 评分助手意图识别：模型优先方案

状态：Accepted（2026-11-17 维护者确认）：Q1 开关默认打开；Q2 只加 `list_rubrics` 与 `list_tasks`；Q3 暂不授权真实模型评测；Q4 与模型管理页方案分开提 PR。

## 1. 现象

2026-11-17 用户反馈，评分助手连基本问题都识别错（助手模型是智谱 `glm-5.3`）：

| 用户原话 | 助手的反应 | 应该怎样 |
|---|---|---|
| 我的评分模板有哪些？ | 反问“是查看当前使用的，还是上传新的？” | 列出可用的评分标准 |
| 查看所有的评分模板 | 同样反问 | 同上 |
| 查看当前已导入的评分模板列表 | 启动“用我的评分规则和模板”导入流程（8 步） | 同上 |

## 2. 根因

一句话进来后的识别顺序（`runner._handle_message`）是：附件 / 快捷按钮 → 按钮原文 `fast_command` → **Agent 回合** → 正则规则 `match_rules` → 规则认不出时才调模型 `intents.interpret`。

1. **GLM 走不到 Agent**：Agent 只对评测达标的模型开放（`agent/evaluated.py`，目前只有 `gemini-2.5-flash`）。`glm-5.3` 不在名单里，整句话退回“规则优先”。
2. **正则匹配过宽**：`import_rubric` 的规则是 `(上传|导入|…).{0,6}(评分模板|…)`，“已**导入**的**评分模板**列表”刚好命中，被当成“要导入”。规则命中后不会再问模型，模型没有机会纠正。
3. **意图表缺少“列出评分标准 / 任务”**：规则模式只有 10 个意图（开始评分、导入、进度、某份扣分、复核、整体、重试、取消、帮助、未知），没有“我有哪些评分标准”。前两句没有命中规则，交给了模型；但模型能选的意图里没有对的那一项，只好反问。

结论：问题出在“规则优先”和“意图表太窄”，而不是代码参与了识别。完全去掉代码也不可取，原因见第 4 节。

## 3. 方案

### 3.1 规则模式改成模型优先

Agent 不可用（模型没评测过、开关关闭、当日回合数用完）时，识别顺序改为：

1. 附件、快捷按钮、按钮原文（`fast_command`）、打字回答选择卡片：照旧由代码直接分派。这些都是精确匹配，不会误判，也不花钱。
2. **有可用的助手模型（不是 Mock）时，先调模型识别意图**（`intents.interpret`，一次调用，正式输出 300 token，30 秒）。
3. 模型失败、超时或输出不合格时，才退回正则规则。
4. Agent 回合刚降级（模型刚出过错）时，这一句直接走规则，不再调模型（与现在相同）。

**保留的代码安全检查**（对模型结果同样生效）：

- `_guard`：问句（“怎么上传模板？”）不触发写操作，改为回答帮助。
- 写操作意图（开始评分、导入、重试、取消）本身都还有后续确认步骤，模型判错不会直接改数据。

### 3.2 补两个查询意图

| 意图 | 说明（给模型看） | 回答 |
|---|---|---|
| `list_rubrics` | 查看我能用的评分标准 / 评分模板有哪些 | 复用 `tools.list_published_rubrics`，用选择卡片（用途 `use_rubric`）列出已发布的标准；同时说明还有几份草稿，附“打开评分标准页”入口 |
| `list_tasks` | 查看我最近的评分任务 | 复用 `tools.list_recent_batches`，用选择卡片（用途 `focus_task`）列出 |

两者不需要先选任务，所以不进查询图，是 `queries.py` 里的两个函数（`list_rubrics` / `list_tasks`），由 `runner` 直接分派。消息的 `intent` 是自由字符串，前端只登记快捷按钮的意图，不用改。

### 3.3 修正规则

规则退为兜底，但仍然要修，模型不可用时会用到它：

- `import_rubric` 的动作词不能是“已导入的 / 导入过的”这种修饰语：`导入` 前面不能是“已”，后面不能紧跟“的 / 过”。
- 新增 `list_rubrics` 规则：`(有哪些|哪几个|列表|列出|查看|看看|所有).{0,8}(评分标准|评分模板|评分规则)`，或反过来的语序。它排在 `import_rubric` 之前。
- 新增 `list_tasks` 规则：`(有哪些|列表|列出|最近|所有).{0,6}(评分任务|任务)`。

### 3.4 成本与版本

- Agent 不可用时，每句非按钮的话多一次模型调用。只有原话、最近 3 句用户原话、当前任务名和评分标准名会发给模型（与现在的兜底调用相同），不发论文内容。
- `glm-5.3` 强制思考：辅助计划会把输出上限放到封顶值，但 30 秒的等待可能不够。这类调用的超时按能力表放宽到 60 秒，超时就退回规则。
- `ASSISTANT_PROMPT_VERSION` 升到 `assistant-intent@3`（意图表变了）。助手不参与评分，不影响评分缓存，也不需要重新锚定 QWK。
- 开关 `ASSISTANT_INTENT_MODEL_FIRST`，默认值见 Q1。

## 4. 放弃了什么

- **完全删掉代码规则**：模型超时、限流或者没配置时，助手会连“开始评分”都听不懂。规则是零成本的兜底，只是不再优先。
- **直接把 `glm-5.3` 加进 Agent 名单**：部署门槛要求名单里的每个模型都在当前提示词上评测达标，评测需要调用真实模型（见 Q3）。不评测就放行，等于让一个没测过的模型去调写操作工具。
- **只修正则、不改顺序**：说法无穷无尽，正则永远追不上。这次的三句话里有两句根本不是正则的问题，而是意图表里没有对的那一项。
