# 评分细则适用范围方案

状态：已确认（2026-11-11，维护者确认 Q1–Q5 按推荐，提示词按讨论稿）。分两个 PR 落地：
A 评分标准侧（本方案第 3–7 节），B 评分侧（第 8 节，开关默认关闭，QWK 评测后再开）。

## 1. 背景

评分项与原子规则原来都有 `applies_to`（适用范围），默认 `global`，来源是 Excel 的“适用范围”列或
规则编辑器里人工填写；另有 `evidence_policy.judge_scope` 可以人工选“章节内 / 跨章节 / 全文”。Core 评分
只在 `SCORING_JUDGE_SCOPE_ENABLED` 打开时按它取证据（生产没开），找不到章节就退回全文；v1 兼容路径按
章节标题互相包含取文本块。实际几乎全是 `global`，章节匹配靠名字和一张偏工科毕业论文的同义表。

## 2. 维护者的决定

| # | 决定 |
|---|---|
| D1 | 不兼容旧的适用范围：不保留 Excel 列、人工填写与旧推断，按新的范围用法设计。 |
| D2 | 每条规则的适用范围在起草细则时由模型识别并返回，不由人指定。 |
| Q1 | 范围用章节角色表示，按 Profile 固定一张角色词表，严格 Schema 用枚举限定。 |
| Q2 | 不经过起草的规则（Excel 已解析的扣分规则、导入的原子规则）由单独的“范围识别”AI 任务补上。 |
| Q3 | 论文标题先用代码同义表对到角色，对不上的标题让模型归类一次（每篇只发标题列表），结果冻结进这篇论文的评分记录。 |
| Q4 | 论文里找不到目标章节时不调用模型，直接转人工复核。 |
| Q5 | 已发布的旧规则在重新起草或做范围识别之前一律按全文处理。 |

## 3. 范围的表示

```json
{"type": "section", "sections": ["绪论"]}
```

- `type`：`document`（全文）、`section`（一章）、`cross_section`（多章对照）。
- `sections`：角色名，取自所属 Profile 的词表。`document` 为空；`section` 恰好 1 个；`cross_section` 2–3 个、互不相同。
- 词表版本 `section-roles@1`，代码在 `services/rubric_scope/vocabulary.py`：

| Profile | 角色 |
|---|---|
| `thesis` | 摘要、绪论、文献综述、研究方法、需求分析、系统设计、系统实现、测试与实验、结论、参考文献、致谢、附录 |
| `general_document` | 摘要、引言、背景、方法、结果、讨论、结论、参考文献、附录 |
| `technical_proposal` | 项目概述、需求分析、总体方案、详细设计、实施计划、风险分析、经费预算、团队与组织、预期成果、附录 |

每个角色带一组标题同义词（例如“绪论”对“引言、前言、研究背景、Introduction”），评分时用来把论文标题对到角色（第 8.1 节）。
词表只用于范围，不改变评分项本身的结构。

## 4. 存储

- 新列 `atomic_rules.scope`（JSON，可空，迁移 `0044_atomic_rule_scope`；不建表，不涉及 `pgs_app` 授权）。
  值为第 3 节的对象再加 `source`（`ai_draft` 起草返回 / `ai_identified` 范围识别）与 `vocabulary`（词表版本）。
- **空即全文**（Q5）：旧规则、识别失败的规则都按全文处理。
- 版本内容哈希：`scope` 非空时进入规则的哈希内容，为空时不出现。0044 之前已发布的版本重算出的哈希逐字节不变。
- **不进人工确认的签名，也不进 `content_token`**：范围变了，规则不回到“待确认”，打开着的编辑表单也不失效。范围由模型决定、老师不填写，要老师为它逐条重新确认，等于又把它交回给人。
- **重新编译时带过去**：人工与 Excel 行每次从评分项投影重新编译，编译不会给它们范围；内容与评分上下文未变的规则沿用前一版的范围，变了的留给下一次识别。
- `applies_to` 与 `evidence_policy.judge_scope` 不再接受人工的新值，列保留（删列要另做迁移，且有历史数据）。分期 B 起 Core 评分不再读它们；v1 兼容路径照旧读 `applies_to`（第 7 节）。

## 5. 起草时返回范围（提示词 `rubric-rule-draft@10`）

- 规则组加 `scope` 字段，放在组上不放在单条规则上：同一个互斥组的各档必须看同一批证据。
- 输入 `payload.scope_vocabulary` 给出本 Profile 的角色与说明；严格 Schema 用枚举限定 `type` 与 `sections`，精简 Schema 同样保留这两个短枚举。
- 校验 `validate_ai_rule_draft`：类型与章节数按第 3 节的规则检查，角色必须在词表里；不合格按 `AI_DRAFT_OUTPUT_INVALID` 走一次修正。
- 前端把组上的 `scope` 复制到每一行结构化扣分（`ai-draft.js`），编译时只有可归属的 AI 行（`source` 以 `ai_` 开头、带生成指纹与草稿行键）的 `scope` 写进细则；人工与 Excel 行上即使写了也忽略（D2）。
- 起草不用 L0 缓存，不改 `llm_cache.PROMPT_VERSION`。互斥组方案分期 B 原定的 `@10` 顺延为 `@11`。

## 6. 范围识别任务（Q2，AI 任务种类 `rule_scope`）

- 对象：当前执行草稿里参与评分、`scope` 为空的语义规则（确定性规则不取证据，不识别）。评分标准必须是草稿状态；已发布的先“新建草稿”。
- 每个评分项一个条目；输入是评分项的名称与说明、这些规则的编号、名称与规则文字、本 Profile 的词表；输出每条规则的范围。
- 校验与起草相同；编号不在输入里、范围不合格的条目丢弃并计数，修正一次后仍不合格就记为这一项识别失败，其余评分项照常。
- 全部条目结束后原地写进草稿规则的 `scope`（`source=ai_identified`），并给编译记录追加审计事件 `scope`；不改规则状态（第 4 节）。
- 页面：第 2 步规则面板“识别适用范围”按钮（老师发起任务，不填写范围），完成后在规则上只读展示。
- 估算走 `…/estimate`，不调用模型；与其它 AI 任务一样冻结输入、锁定连接、按内容指纹去重。

## 7. 去掉人工指定范围的入口（D1、D2）

- Excel 的“适用范围”列不再决定评分范围。它仍写进 `applies_to`，但只用来给 Word 模板批注找对应规则（导入时生成、由老师确认的关联提示）。分期 B 起 Core 评分的范围只来自 `atomic_rules.scope`；在那之前评分沿用现有取证逻辑。
- 规则编辑器去掉“适用范围”输入框与“判定范围”下拉框，改为只读显示范围和来源；
  `lifecycle` 的可编辑字段去掉 `applies_to`；修改里带的 `evidence_policy.judge_scope` 不保存，规则上已有的值原样保留（分期 A 不改评分，开关打开的部署里旧评分路径还读它；分期 B 起不再读）。
- 以上是分期 A 已做的。评分侧的两项在分期 B：`judge_scope.py` 里按 `applies_to`、人工判定范围与规则文字推断范围的逻辑删除，范围只来自 `atomic_rules.scope`；v1 兼容路径（未版本化的旧标准）按 `applies_to` 取章节文本块的分支**不改**，它不经过 Core，改它要单独做 QWK。分期 A 合并后、分期 B 合并前，评分仍按旧推断（生产开关没开）。

## 8. 评分时应用范围（PR B，`SCORING_JUDGE_SCOPE_ENABLED`，默认关闭）

开关沿用原名，含义改为“按细则的适用范围取证据”。关闭时与现在的生产行为相同：规则快照 `@3`、全部按全文，
也正是 Q5 对旧规则的处理。打开时规则快照升为 `atomic-rule-snapshot@5`（带 `scope`），旧的 `@4` 删除。

### 8.1 论文标题对到角色（Q3）

1. 每个证据单元的标题路径逐级用词表同义词匹配，命中的第一级决定角色（编号“第 1 章”“1.2”先去掉）。
2. 有规则需要章节、又有一级标题没对上时，把**没对上的一级标题列表**发给模型归类一次（`complete_json`，严格 Schema，角色枚举加“无”）。不发正文。
3. 结果冻结进这篇论文的评分记录（`profile_prompt_extensions.section_roles`，进入信封身份），同一篇论文的所有规则共用。模型调用失败只用第 1 步的结果，记日志，不让整篇失败。

### 8.2 取证据

| 范围 | 给模型的证据 | `coverage` |
|---|---|---|
| 全文 | 全文按相关度取前若干段（同现在） | — |
| 一章 | 只给这一章的段落；整章放得下就全部给出，放不下才在章内排序截取 | `complete` / `partial` |
| 多章对照 | 每个目标章节都给，按章节分组、交替取 | 每章各自标 |

`SCORING_EVIDENCE_SCOPE=criterion` 时，只在范围相同的规则之间共用同一批证据。

### 8.3 找不到目标章节（Q4）

目标章节（多章对照时任意一章）在论文里一段都没有：不调用模型，判定记为 `not_triggered`，带复核问题
`RULE_SCOPE_SECTION_MISSING`，所属评分项转人工（与“证据不足”同一条路径）。不退回全文。

### 8.4 提示词

系统提示词在判断指令后固定追加一段，按范围类型写死、不随规则变化（便于厂商提示词缓存）：

> scope 说明本规则评价论文的哪一部分，由系统确定，你不得更改。type=document：evidence 是从全文按相关度选出的段落，
> 不是全文。type=section：evidence 只来自 scope.sections 列出的章节；coverage=complete 表示给出了该章节的全部段落，
> partial 表示只给出了部分。type=cross_section：规则要求对照多个章节，每条 evidence 的 section_role 标明所属章节。
> 只依据 evidence 判断，不得推测范围外或未给出段落的内容。规则要求的内容在 evidence 里找不到时：coverage=complete
> 可以判 triggered；coverage=partial 或 type=document 时判 insufficient_evidence，不能判缺失。cross_section 判 triggered 时，
> occurrences 必须分别引用至少两个不同章节的证据。

视图里 `scope` 写成 `{type, sections: [{role, headings, coverage}]}`，每条证据带 `section_role`。
范围开关打开时，非分档规则一律允许 `insufficient_evidence`（“完整 / 部分”的区分离不开它）。

### 8.5 返回后的检查

- 多章对照判 `triggered` 时，引用的证据必须覆盖至少两个目标章节；不满足就不采用这次判定，记复核问题 `RULE_SCOPE_CITATION_INCOMPLETE`，评分项转人工。
- 引用只能来自给出的证据，这一条原有的校验已经保证。

### 8.6 版本

- 判断视图的提示词版本后缀加 `+rule-scope@1`；`judge-scope@1` 升为 `judge-scope@2`（进入证据选择身份）。
- 决策账本按身份区分，开关前后的判定不会互相复用。

## 9. 评测（需单独授权）

- 起草提示词 `@10`：合并 PR A 前用合成模板做一次真实模型起草评测，看范围是否合理、规则数与分值是否退化。
- 评分侧：打开开关前用 QWK 留出集重新锚定（CLAUDE.md），与“证据不足”“判定理由”两个开关一起做那次联合评测。
- 两者都需要维护者授权预算，本方案的实现不调用真实模型。

## 10. 放弃了什么

| 放弃的做法 | 为什么 |
|---|---|
| 范围写自由章节名 | 起草时还没有论文，写不出真实标题；自由名字评分时更难对上（Q1）。 |
| 范围放在单条规则上 | 同一互斥组的各档会看到不同证据，组判断失去意义。 |
| 复用 `applies_to` + `evidence_policy.judge_scope` 存范围 | 旧数据是人工自由填写的，和模型返回的分不开；Q5 要求旧规则按全文，需要一个“空即全文”的新字段。 |
| 范围变化让规则回到待确认 | 等于又让老师为范围逐条负责，和 D2 矛盾；代价是老师确认规则时看到的是确认那一刻的范围。 |
| 不经过起草的规则一律按全文 | 导入的评分标准就永远用不上范围（Q2）。 |
| 论文标题只用代码同义表 | 非工科、非标准标题对不上就悄悄退成全文；模型只看标题、每篇一次，成本很小（Q3）。 |
| 找不到章节退回全文 | 模型拿着不相关的段落判断，结果看起来正常其实没有依据（Q4）。 |
| 不加开关直接生效 | 评分逻辑变了要先做 QWK；develop 还要照常发布别的改动。 |

## 11. 风险

- 词表覆盖不全：新类型文档的章节没有对应角色，模型只能选全文。词表改动要升 `section-roles` 版本。
- 角色对不上：一章被误判为别的角色会让规则看错证据；第 8.1 节第 2 步与复核问题 `RULE_SCOPE_SECTION_MISSING` 兜底，打开开关前要用真实论文看对应率。
- “完整 / 部分”依赖整章能放进预算；章节很长时多数是 `partial`，缺失类规则会更多转人工。
